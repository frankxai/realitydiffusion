# Reality Diffusion — Agent Contract

## Purpose

Build Reality Diffusion as a trustworthy synthetic-media intelligence product: help people understand, create, and verify AI-mediated media.

## Product boundaries

- Do not collapse the product into Reality Architect or Arcanea.
- Do not reuse the 2025 `RealityDiffusionX` application wholesale. It is archaeology only.
- Do not publish simulated authentication, fake premium gates, invented experts/comments, or non-working generation claims.
- The initial Reality Check is local-only: no upload, model call, account, payment, or remote persistence.

## Design direction

- Investigative editorial register: evidence desk, source notes, signal classification, provenance.
- Avoid generic AI gradients, glass-card grids, stock robots, WebGL spectacle, and vague platform claims.
- Semantic HTML, visible focus, keyboard completion, 44px touch targets, reduced-motion support, and responsive recomposition are mandatory.
- Prefer CSS and server-rendered content. Client JavaScript is limited to interactions that require state.

## Workflow

- `main` is protected release scaffolding.
- Feature work uses `agent/<harness>/<scope>` branches.
- Tests precede behavior changes.
- Required release commands: `npm run verify` and `npm run build`.
- A Vercel preview is required before attaching `realitydiffusion.ai`.
- Domain, production deployment, credentials, payments, public submissions, and destructive operations remain explicit release gates.
